📖 Guidance — HTML Structure & Game Logic ▼

Goal

Teach key vs index list reconciliation. Each portrait has a key (identity) and state (glow/emoji). Key-matched keeps state with the key; index-matched keeps state at the position.

HTML Structure (single file)

<header> stats + sound, .stats score/best/level, .timer-wrap bar, #viewChapters chapter cards, #viewGame mansion + op-banner + options, #viewResult summary, <details.guide> docs. All CSS inline, no external requests. Max-width 428px, no horizontal scroll, 44px+ touch targets.

Game Logic

20 puzzles = 4 chapters ×5. Operations: insert, delete, reorder, update. For each puzzle we compute correct (state follows key) and wrong (state stays at index). Wrong visuals = initial visuals by position, not by key. Player picks correct side (randomized). 30s timer, 3 lives/chapter, 3 hints/chapter. Score = 100 + timeBonus + streak. Persist localStorage.hauntedListsSave = {bestScore, unlocked}.

Key vs Index Visual Rule

Insert at pos: wrong = old visuals stay, new key gets old visual. Delete: wrong = first N visuals stay. Reorder: wrong = visuals stay at positions. Update: wrong = new visual applied to position, not key.

Mobile-first

Portrait 360-428px, grid 2-4 cols, large option cards, readable 12-16px text, no zoom needed, no horizontal scroll.
